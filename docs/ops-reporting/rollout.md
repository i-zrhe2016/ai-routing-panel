# 灰度发布与回滚

> 权威范围：Prometheus-only 上线顺序、验收节点和回滚

## 分阶段发布

1. 在单个非关键节点安装 exporter，配置只允许 Prometheus 源访问的防火墙。
2. 加入 Prometheus target，观察至少 30 分钟的抓取稳定性、标签和基数。
3. 扩展到普通数据面与 AI 数据面；仅生成影子报告，不作为值班依据。
4. 连续两个报告日通过人工对照和安全验收后，启用正式发布。
5. 每次 exporter、标签、查询或阈值变更都按同一路径重新灰度。

## 回滚触发条件

未授权网络可访问 exporter、节点资源明显回退、标签冲突、Prometheus 基数异常、持续 target down、规则误报或报告发布不一致时立即回滚。

## 回滚步骤

1. 停止正式日报调度，保留已发布报告和 SQLite 审计。
2. 从 Prometheus 移除新增 target 或恢复上一版抓取配置并 reload。
3. 恢复上一版 exporter；若需卸载，先确认不影响 Xray 数据面进程。
4. 恢复原防火墙规则，确认指标端口不再可达或仅旧 target 可达。
5. 验证 Xray 流量路径不受影响，并记录触发原因、版本和时间。

禁止回滚到 SSH/原始日志采集方案。SQLite 无需回滚为遥测存储；它继续仅保留审计和历史索引。
